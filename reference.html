Badge

An outlined 24px status label; the status shows in the outline and dot, never in the label colour.

Figma 139:395 contract: review guidance: proposed the portfolio site .badgethe accounting app .ak-badge 4 variants
statusDefaultNegativePositiveWarning
Partsrooticonicons-dotunionlabeloutline

When to use

  • To tag an item with a status in a list, card or table row: Paid, Overdue, Draft.

When not to use

  • To announce something about the page, use InlineBanner.
  • To categorise (topic, type) rather than report a status, use Tag.
  • If it should be clickable, use Chip. Badge has no interactive states.

Behaviour

status sets only the outline (non-interactive/background/<status>/light) and the leading dot. The label stays non-interactive/foreground/tertiary in every status, on purpose: the kit keeps badges quiet. There is no background fill. Those are the three things the first accounting-app Badge got wrong.

Accessibility

  • Element: a <span>, not interactive.
  • Colour: the outline alone is not enough. The label must name the status ("Overdue", not "!").
  • Dot: aria-hidden="true".

Content

One or two words, sentence case, no punctuation.

Button

A label-only action at 48px, in four levels of emphasis.

Figma 39:38 contract: review guidance: proposed not implemented yet 20 variants
typeBorderlessPrimarySecondaryTertiary
statesDefaultHoverPressedFocusDisabled
Partsrootlabelbackgroundfocus-ring

When to use

  • To start an action: submit, save, continue, open.
  • Primary for the one action a view is built around. One per view, at most.
  • Secondary for alternatives next to it, Tertiary for low-stakes actions, Borderless inside dense surfaces where an outline would be noise.

When not to use

  • If the action needs an icon to read, use PillButton. If it is icon-only, use IconButton.
  • To go somewhere, use a link. A button that navigates loses open-in-new-tab and history semantics.
  • To choose one of several options, use Toggle or Chip.

Behaviour

type sets emphasis. state is never a prop in code: Hover, Pressed and Focus come from :hover, :active and :focus-visible. Disabled is the only state the caller sets. The background drops to opacity/gentle while the label stays legible.

Accessibility

  • Element: <button type="button"> (or type="submit" inside a form).
  • Name: the visible label. Never replace it with aria-label text that differs.
  • Keyboard: Enter and Space activate.
  • Focus: the focus-ring part, 2px, drawn on :focus-visible only.
  • Disabled: prefer aria-disabled="true" with an explanation nearby over disabled, which removes the button from the tab order and hides why it can't be used.

Content

A verb, sentence case, two or three words: "Save changes", not "OK" or "SUBMIT". The label states the outcome.

Hero Media

The full-bleed case-study hero, artwork pinned behind a 16px inset frame and dimmed to one shared level.

Figma 245:2900 contract: review guidance: proposed not implemented yet
Partsheroframemedia
hero
Full-bleed section, 630px tall, background colour non-interactive/background/primary. Its padding is the 16px inset frame that shows the page background around the framed image. The width must subtract the real scrollbar width (100vw includes it), or the visible left/right inset reads ~8px while the top reads 16.
frame
The window onto the artwork: fills the hero inside the 16px inset, radius/xlarge corners, overflow hidden (clip-path inset round when the media uses position:fixed descendants).
media
The artwork layer: a background-image div, never an <img> (background-attachment needs a background).

When to use

  • At the top of every case study on the portfolio site. One per page.

When not to use

  • For the home page hero, which uses the Paper effect instead of artwork.

Behaviour

Accessibility

  • Artwork: a background image, so it is decorative by construction. Anything the reader needs from it goes in the text.
  • Contrast: text over the hero is checked against the dimmed artwork, not the underlay colour.
  • Motion: pinned parallax is turned off under prefers-reduced-motion.

Declared deviations

  • All apps: Media opacity is opacity/medium (0.48) on a #171717 frame underlay; the Figma node specifies 32% (opacity/mild). Unified hero dim decided 2026-10-18 across all case studies: perceived dim is opacity × underlay, and three heroes read darker at the same opacity. Figma not yet updated.

Paper effect

The dot-lattice sheet behind the the portfolio site hero, which responds to the cursor, the CTAs and presses but never moves on its own.

portfolio-site/src/components/HeroBackdrop.jsx contract: review guidance: proposed the portfolio site
Partssheetdotlensripplepen
sheet
A canvas of dots behind hero content. Shaped by a CSS mask — on the portfolio site a 1104px disc centred on the hero content block (radial-gradient circle 552px, solid to 40%, dissolved by 92%) — and sized so the lattice is anchored to the content, not the container. Idle cost is a single static frame; prefers-reduced-motion gets the still sheet and none of the behaviours below.
dot
One lattice point. Never animates on its own: it only RESPONDS (lens, ripple, pen). The paper must never twinkle.
lens
The dome field all behaviours share. Three sources: the cursor (the magnifier), the CTA halo (hovering a hero button raises a lens under the button's centre - the control presses into the paper), and press ink (pointer down dents the sheet, deepening fast and relaxing slowly on release). Sources sampled per dot, the strongest wins - lenses never stack. Dots inside grow proportionally and are pushed outward; they never multiply and never change character.
ripple
A ring (gaussian band, ~1.8s) crossing the sheet from its centre. Fired by the availability dot's own pulse animation (animationiteration on the banner dot) every SECOND ping — 8s, phase-locked, never a free-running timer. Runs only while the hero is on screen.
pen
Every 7-8s one kit component is sketched in 2px strokes (stroke colour = non-interactive/foreground/secondary at the ink opacity): drawn stroke by stroke (~1.6s), held (~3s), faded. THE LATTICE LAW: outer shapes run exactly along dot rows/columns — origin snapped to the lattice, dimensions in whole cells, corners arcing between lattice points. Inner elements (check, x, knob, bars, caret) keep natural proportions instead. Strokes are polylines whose every vertex rides the lens field, so ink bulges under the blurb like the dots do. One sketch at a time.

When to use

  • Behind the home hero only. It is the site's signature, and repeating it dilutes it.

When not to use

  • Behind dense content or forms: the lattice competes with text at small sizes.

Behaviour

The dots only respond, through the lens, ripple and pen behaviours described in the anatomy. They never animate on their own. Everything snaps to the 16px lattice pitch. It is idle at one static frame, and runs only while the hero is on screen.

Accessibility

  • Decorative: the canvas is aria-hidden="true" and takes no focus.
  • Motion: prefers-reduced-motion gets the still sheet and none of the behaviours.

  • Name: aria-label when icon-only.
  • Focus: focus-ring (2px, actions/primary/focus/focus-ring when selected), on :focus-visible.
  • Colour: selection is carried by shape (radius 12px → full) as well as colour.

Icon-only in the kit. accounting-app adds a text label as a declared deviation. Keep any label to one short word or a number.

  • the accounting app: Accepts a text label; width grows past 40px to fit it, height stays 40px. Label colour follows the surface: secondary label unselected, primary label selected. The year switcher needs text. The kit's toggle is icon-only and specifies no label colour.
